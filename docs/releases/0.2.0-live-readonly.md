# AM Account 0.2.0 — live service access test

First live-data, read-only test APK. This is a development/debug-signed prerelease, not a production customer rollout.

## Try it

1. Download and install `AM-Account-0.2.0-live-readonly-test.apk` on Android 8 or later.
2. Open **AM Account**.
3. Use an authorized customer's six-digit Hub activation code, or select **Username & password** and enter their service credentials.
4. Compare the displayed account status, expiry, and connection count with the provider panel.
5. Try refresh, channel-group search, and sign-out.

The app uses its own implementation and memory-only session. Hub's code, deployment, profiles, and login are unaffected. AM calls the same existing provider endpoints, not a newly deployed AM authentication server.

## Working in this build

- Activation-code and direct-credential login against the real provider endpoints.
- Account status, expiry, connection counts, trial status, and available channel groups.
- Package name only when explicitly supplied by the provider.
- Refresh with stale-data warnings on network failure, and account removal if authorization is rejected.
- Sign-out and request cancellation. Process restart requires signing in again.

## Not connected yet

Invoices, account credit, payments, renewals, service changes, persistent sign-in, and automatic APK updates. Their live screens show setup pending rather than demo records. Missing provider fields are labeled not provided.

## Verification

18 automated protocol/session tests pass; APK build succeeds; Android lint has no errors. Real customer credentials have not been used in development. Native device acceptance remains to be completed by an authorized tester; the development environment's emulator lacks KVM access.

See `docs/live-account-integration.md` for endpoint details and a fuller device checklist. Do not include activation codes, passwords, or customer data in public GitHub issues.
