# AM Account 0.2.1 — remembered login

Development/debug-signed test update for the existing live read-only APK. Install over 0.2.0; the application ID and test signing key are unchanged.

## Changes

- Remembers a successfully verified activation code or service username/password using AES-256-GCM with an app-specific Android Keystore key.
- Re-verifies the saved login automatically on restart. Temporary network problems offer retry without retyping credentials.
- Sign-out removes the saved login. Rejected or unreadable saved credentials require a new login.
- Removes category requests and category screens. Services now includes a bouquet-only section, showing setup pending until AM's worker can supply the real assignments.

Sign in once after this update: 0.2.0 did not save your credentials. Then close/force-stop and reopen to test automatic sign-in. Use **Sign out** when you want AM to forget the account.

No changes were made to Hub or the reseller panel/worker. Billing, bouquet editing, and payment actions remain unavailable until AM's own backend is connected. This update does not create a new worker deployment.

All 27 automated tests pass, the APK builds, and Android lint reports no errors. Tests cover encrypted storage format/tampering, login restoration, offline retry, rejected login cleanup, sign-out, and late responses. The APK's signing certificate matches 0.2.0. Android Keystore/device force-stop behavior still needs verification on a real phone; the development emulator lacks KVM access.
